# 帧变换链与 Oracle 初值

约定 `T_A_B` 把 B 系向量变换到 A 系。

官方 GT 页面说明：GT 的核心是将各 Ouster scan ICP 配准到 Leica prior map；stereo 版本 GT 的位姿以 RS_C1 表示。平台页说明 RS_C1 是左相机 optical frame，base 原点与其重合，但 base 轴为机器人约定（x-forward、y-left、z-up）。因此“GT 来自 LiDAR-to-map 配准”并不自动意味着 CSV 四元数就是 Ouster LiDAR 姿态；RS_C1 光学轴、base 轴和传感器轴仍须区分。

标定输入：

- Kalibr 的 `T_cam_imu` 是 Ouster IMU 到 RS_C1 的标定变换 `T_C_I`。
- Ouster 外参文件的 `os1_lidar_to_os1_imu` 给出 `T_I_L`，平移 `[-0.006253, 0.011775, -0.028535] m`，四元数 `[0,0,-1,0]`。
- 平台轴关系使用 `T_C_B`，其旋转为 `[[0,-1,0],[0,0,-1],[1,0,0]]`，把机器人 base 轴表示的向量映到相机 optical 轴。

GT CSV 的匹配记录时间与扫描 header 完全一致：`1583836591.182590976`。该行原始位置为 `[-3.355590, 8.254200, 0.145701] m`，四元数 `(qx,qy,qz,qw)=[0.0039575,0.00400042,-0.605941,0.79549]`。

## 官方文档帧链（默认配置）

按官方 GT 文档，CSV stereo pose 以 RS_C1 optical frame 表示，记作 `T_M_C`；相机/IMU Kalibr 矩阵为 `T_C_I`，Ouster 标定给出 `T_I_L`。因此直接的标定链是：

```text
T_M_I = T_M_C × T_C_I
T_M_L = T_M_C × T_C_I × T_I_L
p_M = T_M_L × p_L
```

对冻结行计算：

```text
T_M_I =
[ 0.213403346854, -0.181175124532, -0.960018013270, -3.37066155;
 -0.685679231963,  0.672196415767, -0.279277585003,  8.23471164;
  0.695918818833,  0.717863185350,  0.019220944628,  0.07006124;
  0,                0,                0,                1]

T_M_L =
[-0.213403346854,  0.181175124532, -0.960018013270, -3.34673518;
  0.685679231963, -0.672196415767, -0.279277585003,  8.25488349;
 -0.695918818833, -0.717863185350,  0.019220944628,  0.07361402;
  0,                0,                0,                1]
```

旋转正交误差约 `1.0e-15`，determinant `1.0000000000000007`。但是该直接链在冻结扫描上的最近邻几何 gate 失败：median `19.298385 m`、P90 `40.775133 m`、0.5 m 覆盖率 `0.02714`、2 m `0.12786`、8 m `0.27000`；因此没有对该初值调用 NDT。

## 条件性替代解释（非官方认证）

早先运行曾将 GT 四元数按机器人 base 轴解释，位置取 RS_C1/base 共点原点，构成 `T_M_B`。然后：

```text
T_B_I = inverse(T_C_B) × T_C_I
T_M_I = T_M_B × T_B_I
T_M_L = T_M_I × T_I_L
p_M = T_M_L × p_L
```

得到 `T_M_I` 平移 `[-3.3906651773, 8.3225539939, 0.1663355647] m`，`T_M_L` 平移 `[-3.3771578626, 8.3231144342, 0.1378885048] m`，其旋转为：

```text
[ 0.4974830623, -0.8674501574, -0.0063896105;
  0.8668272934,  0.4973831759, -0.0349345049;
  0.0334820266,  0.0118406357,  0.9993691777 ]
```

该条件链旋转通过 proper-SO(3) 校验，冻结扫描几何 gate median/P90 为 `0.178773/0.445447 m`，0.5 m 覆盖率 `0.925`；随后真实 NDT 收敛。但该姿态解释与官方 RS_C1 optical 标签存在冲突。没有 GT exporter 的姿态轴实现来解释这一差异，故不能将条件链升级为官方事实，也不能把其 NDT 成功当作正式坐标合同通过。它只通过显式 `initialization_override` 配置复现。

先验 PLY 转成 PCD 时只改变存储格式，10,277,007 个点的全部 XYZ 坐标逐点相等，最大差为 0。没有应用 PCD `VIEWPOINT` 或额外静态 TF；地图话题和 NDT 输出共用 `newer_college_map`。NDT 输出 pose 的目标帧是地图坐标，传感器 pose 按 `os1_lidar` 处理。

官方参考：[GT 生成与 RS_C1 定义](https://ori-drs.github.io/newer-college-dataset/ground-truth/)，[平台传感器轴定义](https://ori-drs.github.io/newer-college-dataset/stereo-cam/platform-stereo/)。
