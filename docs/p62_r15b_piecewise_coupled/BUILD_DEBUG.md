# Build and test debugging record

This file preserves the actual implementation/test corrections made before the single real 25-frame run. No NDT `align()` call, bag playback, EKF execution, or reference-pose evaluation occurred during these corrections.

1. Initial compile failures: Eigen fixed-size vector range iteration was unsupported by the installed interface; Boost `shared_ptr` required explicit boolean conversion in assertions; PCL 1.10 Gaussian-grid lookup exposed non-const API methods. The code was changed to indexed Eigen access, explicit pointer checks, and mutable access only where PCL requires it.
2. Initial mechanism-test failure: exploratory-minimum mode selected two directions in the test expectation, but the approved contract permits exactly one minimum spectral probe. The test was corrected to assert one probe, leave the remaining formal weak directions unmodelled, and solve only the complementary strong subspace.
3. Initial non-finite test failure: the test expected the weak pose matrix itself to contain NaNs. The implementation instead kept the candidate pose finite while marking the coupled result unavailable and invalid. The test was corrected to check the actual safety contract: unavailable result, no coupled candidate, invalid status.
4. A final test-source comment/guard clarification changed the source SHA after an earlier successful build. The final frozen source was rebuilt from a new clean directory `p62_r15b_piecewise_build_frozen02`; only `final_configure.log`, `final_cold_build.log`, and `final_test.log` are the final build evidence. Earlier logs are retained but are not the final source/binary identity.
5. A helper invocation with `--help` was not supported and returned `FileNotFoundError` for that literal path. It performed no writes and did not alter the frozen manifest. The valid verifier invocation against `PARENT_INPUT_FREEZE.json` subsequently passed 131/131 entries.
6. The first offline reference-evaluation attempt read the 20 selected pose rows after the model-output seal, then stopped before writing an error CSV because it expected `raw_index` in `ASSOCIATION_BOUNDARY_ANALYSIS.csv`; that table exposes `frame_key`. The second attempt corrected the Newer College key but made the same mistaken assumption for GEODE no-reference rows, again stopping before any error CSV. Both failures are preserved as JSON receipts. The third attempt used the actual table key and frozen GEODE frame-to-raw-index map and completed; no model run, NDT call, or candidate decision was repeated. The same 20 selected reference values were parsed once per evaluation attempt, after the model freeze.
7. A historical R14B `sha256sum -c` command was first run from the repository root even though its entries are relative to the R14B archive directory; that invocation failed to resolve the relative paths. It was immediately rerun from the correct archive directory and all entries passed. This did not modify files or affect the R15B model run.
8. The final read-only archive verifier initially looked for binary identities in `CODE_FREEZE.json`; that file stores the run/test hashes as top-level fields, while the detailed binary records are in `BUILD_PROVENANCE.json`. The verifier stopped at the missing JSON key before completing the binary check and made no writes. The corrected check reads each manifest according to its schema.
9. That corrected check found the two binaries present and their SHA256 values matched the recorded hashes, but the byte counts in `BUILD_PROVENANCE.json` were stale. `stat` showed 560,992 bytes for `run_piecewise` and 413,896 bytes for `test_piecewise`; only those metadata counts were corrected. No binary was rebuilt or modified.
10. The staged whitespace check reported trailing spaces in the two raw CMake configure logs. These are preserved tool-output evidence and were not edited; whitespace validation is therefore applied to all other staged files while excluding only `configure.log` and `final_configure.log`.
11. One final `sha256sum -c` invocation was made from the repository root even though `checksums.sha256` contains archive-relative paths, so that invocation could not resolve its entries. The same manifest had already passed when checked from the archive directory; this wrong-directory invocation was a verification-command error only and changed no files. The manifest is regenerated after this note and rechecked from its owning directory.

No thresholds, NDT parameters, data frames, or research settings were changed in response to data outcomes; no real-data outcomes had yet been generated at this point.
