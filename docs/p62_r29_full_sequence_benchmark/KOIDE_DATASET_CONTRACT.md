# Koide admission — in progress, no accuracy read

Official record https://zenodo.org/records/10122133 (v1,2023-11-14) supplies indoor_easy_01,indoor_hard_01, their exact corresponding map_indoor_easy/hard.ply and GT bundle. Only these five payloads are requested, not the17.2GB collection. Metadata and byte ceilings are frozen in sources/zenodo_record.json. Each payload must pass publisher MD5; local SHA256 is also retained. A20GiB free-space reserve is enforced.

Important sensor qualification: these **indoor** sequences use Microsoft Azure Kinect depth point clouds, not Livox/Ouster LiDAR. Their ROS2 topics are /points2/decompressed sensor_msgs/msg/PointCloud2 and /imu sensor_msgs/msg/Imu. An executed indoor experiment must be called range/point-cloud–IMU–NDT–EKF, not falsely described as rotating LiDAR acquisition. Outdoor sequences are out of scope.

Publisher explicitly defines T_lidar_imu=[.003,.004,-.051,-.476,.474,.524,.525] in xyz/xyzw, mapping IMU to cloud. Quaternion must be normalized for its published rounding, without estimating a new extrinsic. T_map_lidar comes directly from each TUM GT row; T_map_imu=T_map_lidar inverse(T_lidar_imu). Published trajectory is batch optimized from point registration and IMU motion residuals, not independent mocap. Map building provenance beyond the supplied benchmark is not presumed independent survey.

Only header stamps drive sensor time, SI angular velocity/linear acceleration preserved. No unstated deskew point-time is inferred. If raw depth messages have no point times, retain them as instantaneous range images at header stamp, with explicit zero offsets; existing deskew math then has no intra-frame motion interval. Do not invent a spinning scan duration. Original measurements and adapter equivalence receipts must be verified before formal use.

The ROS2 adapter preserves every selected PointCloud2/IMU message in count/time order. It emits original float32 XYZ bit patterns plus explicit t=0, strips only unused color/padding, and retains original ROS2 data. XYZ is checked bitwise for all points after rereading PCD, including NaN payloads. All gyro/accelerometer doubles and integer stamps are checked after CSV roundtrip; raw CDR hashes, original fields/frame IDs and bag/header time differences are logged. Added zero time is a declared snapshot approximation, not a measured camera exposure model. The existing deskew implementation is unchanged.
