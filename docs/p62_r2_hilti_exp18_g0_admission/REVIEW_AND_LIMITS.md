# 本地复核与修正记录

使用Git Workflow隔离分支，Incremental Implementation分阶段归档；Doubt-driven Development触发新上下文只读反证，Debugging技能按实际保护缺口修正，Code Review按正确性/路径安全/资源边界核对。技能引用的本地definition-of-done补充文件不存在，未据此暂停任务，采用任务明示门限和实际测试兜底。

三类复核：

1. 下载器保护：发现free检查未计下一块写入；路径检查在mkdir之后；默认socket inactivity timeout不等于总期限。分别修正写前余量、创建前祖先检查、SIGALRM总期限。后续又关闭“已有asset在目录检查前读取”的路径。
2. Range与小文件发布：发现缓存直接写最终路径、源缓存可经符号链接越出内盘；已统一独立stage+verify+exclusive link，并校验源路径/设备。当前修复版通过合成回归；原传输代码版本单独记录，且实际未执行其有问题的缓存分支。
3. 坐标来源：只查官方材料，指出README的IMU表述和URDF base约定之间的区别、共同TLS来源不足以单独认证发布文件的数值T_M_W、rpy相机标定不能解释另一份lidar四元数YAML。

17项测试仅测试下载、路径、Range响应和小文件发布；不是17项传感器/定位验证。原始Range传输超时、E57未下载、实际点时间未检查等失败均保留，不以测试通过覆盖。

用户明确选择不追加跨模型复核；本轮Codex/Gemini等外部CLI执行0。R1待确认的外部命令未继承执行权限。

一次R1 checksum命令误从仓库根目录运行，导致相对路径找不到或对错文件；定位为命令cwd错误后，改在R1归档目录核验21项全部通过。不是冻结资产内容变化，未修改R1文件来让检查通过。
