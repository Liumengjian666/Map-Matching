# 38.021059°数值核查

来源：R1封存的首10扫描／185 IMU重建结果及原始ICP打印矩阵，均有SHA；本轮不重新读取bag、不运行配准。脚本 `tools/check_frames.py`，实际成功计算CODE `b8339e277971c87c71d3a0be664e650120f0f722`。数值与断言保存在`evidence/FRAME_NUMERICS.json`。

## 1. 比力与重力符号

加速度计测的是比力，近静止时\(f_I\simeq-R_{WI}^{T}g_W\)，所以世界重力是\(g_W\simeq-R_{WI}f_I\)，不能将f直接当g。本段以初始化ba=0、尺度归一化和近静止为条件，不宣称独立IMU标定。

封存原始均值：[-0.3973784787,0.0256222675,0.9106824105]。单位比力：

```text
u_I = [-0.3998029164, 0.0257785910, 0.9162385564]
g_I (Super units) = [3.9159096451, -0.2524909873, -8.9741901647] m/s²
```

\(\angle(u_I,+Z_I)=23.617764682°\)。这是IMU轴相对重力的初始倾斜，不是最终38.02°，也不是LiDAR–IMU外参旋转。

## 2. 优化前：复现原作者对齐公式

FromTwoVectors加原生去yaw得到（double重建）：

```text
R_pre =
[ 0.9166011281  0.0112441012  0.3996447700 ]
[ 0             0.9996044390 -0.0281241100 ]
[-0.3998029164  0.0257785910  0.9162385564 ]
```

R_pre*u_I=+Z，误差1.239856e-16；R_pre*g_I=-gZ，误差3.347766e-16。正交误差1.720820e-16、det约1。这验证公式与方向，不冒称日志有逐位相同的原生float初值。

## 3. 优化后：封存ICP矩阵

使用记录的R_ICP：

```text
normalize(R_ICP*u_I) = [-0.3778192414, -0.4864651485, 0.7877844122]
implied g_M = [3.7005883414, 4.7647315440, -7.7160332038] m/s²
ESKF retained g = [0, 0, -9.7946] m/s²
```

两种正确符号计算一致：

\[
\angle(R_{ICP}u_I,+Z)=\angle(-R_{ICP}u_I,-Z)=38.021059232°.
\]

对应静止净加速度\(9.7946\,\widehat{R_{ICP}u_I}+[0,0,-9.7946]\)为[-3.70058834,-4.76473154,-2.07856680]，模长6.38102348m/s²。它提示重力与初始化位姿不兼容；不是对真实运动加速度的独立测量，更不是用它修改滤波器。

六位打印矩阵的RᵀR误差6.813720e-6、det=1.000004025。保留原值，仅对方向向量归一化，不通过SVD或位姿误差拟合旋转。首条轨迹四元数只做单位归一化以消除六位打印舍入，不改变源文件。

组合Delta满足Delta*T_pre=T_ICP，误差1.318390e-16；其旋转作用于+Z等于R_ICP*u_I，误差2.482534e-16。它说明38.02°在已记录的配准前后关系中如何出现，但不能认证地图重力变换。没有记录NDT单独终值，故其贡献与ICP贡献不可分辨。

## 4. 独立旧记录的交叉核对

较早运行fastlivo_loop2.log第43行记录g=[3.9234,-0.2524,-8.9878]m/s²，模长9.81006229，对-Z倾角23.62588798°；其负方向与R1 u_I相差0.00878492°。方向高度相符，支持起步姿态及符号解释。

但该日志保存的是468495点的旧地图，不是指定459154点PCD，因此不能把旧g认证为当前g_M。若仅作这一显式条件性比较，ICP后比力与旧-map比力相差30.64508347°，并未因用旧倾斜g替代Z就自动一致。

同目录第一条pose（1786179479.946594）距单位旋转0.21465332°。若与R1静止方向可比，则其世界比力倾角23.70046133°，支持未对齐解释；不同时间／运动、参数及生产绑定仍有限制。
