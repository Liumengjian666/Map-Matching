# C++机器狗端先验地图定位：模块化代码结构说明

时间：2026-08-12

## 1. 为什么拆分

原来的 `dog_prior_map_ekf_node.cpp` 超过1000行，所有功能混在一起，不利于像 FAST-LIVO2 那样逐模块改进。现在已经按功能拆成多个 `.cpp/.hpp` 文件，后续可以单独优化地图、IMU、LiDAR匹配、视觉约束和ROS输出。

## 2. 文件结构

| 文件 | 功能 | 后续主要改进方向 |
| --- | --- | --- |
| `include/dog_prior_map_localization/dog_prior_map_ekf_node.hpp` | 主类声明、成员变量、函数接口 | 新增状态量、参数、模块接口 |
| `src/dog_prior_map_ekf_node.cpp` | main入口，只负责启动ROS节点 | 一般不用改 |
| `src/dog_prior_map_ekf_node_core.cpp` | 构造函数、读取参数、订阅发布初始化 | 新增配置项、接入新话题 |
| `src/map_loader.cpp` | 读取PCD先验地图、降采样、KDTree构建 | 局部子地图、地图分块、地图法向量预计算 |
| `src/imu_processor.cpp` | IMU重力初始化、高频传播、协方差预测 | 接入机器狗腿部里程计、IMU预积分、零偏估计 |
| `src/lidar_matcher.cpp` | LiDAR预处理、点到点/点到面/混合地图匹配 | NDT、点到面优化、退化检测、鲁棒核 |
| `src/vision_and_initial_pose.cpp` | 图像曝光质量门控、RViz初始位姿 | 特征重投影、AprilTag初始定位、视觉约束 |
| `src/ros_output.cpp` | 发布Odometry/Path/TF、实时性CSV | 输出轨迹、调试话题、性能统计 |
| `src/math_utils.cpp` | 数学工具函数 | SO3工具、李代数工具 |
| `scripts/evaluate_runtime_and_accuracy.py` | 离线评估精度、频率、CPU、内存 | 增加ATE/RPE、GNSS真值对齐 |
| `scripts/run_dataset_evaluation.sh` | 一键播放bag并评估 | 批量数据集自动测试 |

## 3. 推荐改进顺序

1. `map_loader.cpp`：先做局部子地图和地图分块，减少错误最近邻。
2. `vision_and_initial_pose.cpp`：加初始位姿对准，比如AprilTag/NDT粗配准/RViz初值。
3. `lidar_matcher.cpp`：加退化检测和自适应权重，解决走廊漂移。
4. `imu_processor.cpp`：接入机器狗腿部里程计，让高频位置传播不只靠IMU。
5. `scripts/evaluate_runtime_and_accuracy.py`：有RTK/GNSS真值后加ATE/RPE。
