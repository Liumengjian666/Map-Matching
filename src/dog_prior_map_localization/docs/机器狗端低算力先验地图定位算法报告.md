# 机器狗端低算力先验地图定位算法报告

## 1. 背景和老师的新要求

之前实现过几套地图匹配方案，包括 FAST-LIO2 作为初值的 location、FAST-LIVO2 作为初值的 location，以及一些外部 map_to_odom 修正方案。这些方案更像是在已有 SLAM/里程计外面再套一个定位节点，适合离线验证，但不完全符合机器狗端部署要求。

老师现在要求的是：

1. 先用 FAST-LIVO2 离线建好地图。
2. 把地图传到机器狗里。
3. 机器狗端运行一个低算力地图匹配定位算法。
4. 算法内部结构是：IMU 高频传播，LiDAR/Camera/先验地图低频约束进入 EKF/IESKF 修正。
5. 输出既要有高频位姿，也要有低频精准修正位姿。

因此本工作区新建了 `dog_prior_map_localization`，作为机器狗部署版原型，不删除原来的几套 location 方案。

## 2. 总体算法框架

```text
FAST-LIVO2 离线建图
        ↓
先验点云地图 PCD / NPZ
        ↓
机器狗实时定位节点
        ├── IMU 高频传播状态，输出 /dog_livo/odom_high_rate
        ├── LiDAR 当前帧与先验地图匹配，构造点云匹配残差
        ├── Camera 图像质量门控，后续可扩展为特征/光度约束
        └── EKF/IESKF 低频更新，输出 /dog_livo/odom_corrected
```

两个低频精准更新之间，IMU 会连续传播很多高频位姿。这正是机器狗控制和导航需要的输出形式。

## 3. 状态量设计

当前原型采用 15 维误差状态：

```text
x = [p, v, R, ba, bg]
误差状态 dx = [delta_p, delta_v, delta_theta, delta_ba, delta_bg]
```

含义：

- `p`：机器狗在先验地图坐标系下的位置。
- `v`：机器狗速度。
- `R`：机器狗姿态。
- `ba`：加速度计零偏。
- `bg`：陀螺仪零偏。

IMU 每来一帧就传播名义状态和协方差，因此 `/dog_livo/odom_high_rate` 可以达到接近 IMU 的频率。

## 4. IMU 高频传播

IMU 预测模型为：

```text
R_k+1 = R_k * Exp((gyro - bg) * dt)
v_k+1 = v_k + (R_k * (acc - ba) + g) * dt
p_k+1 = p_k + v_k * dt + 0.5 * a_world * dt^2
```

这一步不依赖点云和图像，因此算力很低、频率很高。缺点是 IMU 会漂移，所以需要低频观测修正。

## 5. LiDAR 与先验地图匹配约束

当前 LiDAR 更新采用低算力点到点最近邻匹配：

```text
r_i = p_map_nearest_i - (R * p_lidar_i + p)
```

线性化后加入 EKF：

```text
H_i = [I, 0, -R * skew(p_lidar_i), 0, 0]
```

为了适合机器狗低算力部署，代码做了这些限制：

- 当前帧点云先体素降采样。
- 每帧最多使用 `max_scan_points` 个点。
- 地图预先转成 NPZ，启动时构建 KDTree。
- 单次 EKF 更新只迭代少量次数。
- 对大残差使用 Huber 权重。
- 限制单次平移和旋转修正，防止错误匹配把定位拉飞。

## 6. 相机约束当前实现

当前版本先实现了相机质量门控，而不是完整视觉重投影约束：

- 统计过曝比例。
- 统计欠曝比例。
- 计算图像梯度均值。
- 如果图像质量差，则降低视觉/地图相关权重。

这样做的原因是机器狗端算力有限，而且室外曝光变化会影响视觉直接法。后续可在 `image_callback()` 中继续加入：

- 特征点重投影残差。
- 语义边缘约束。
- 光度误差约束。

## 7. 文件说明

### `scripts/dog_prior_map_ekf_node.py`

主算法节点。包含：

- 参数读取。
- 先验地图加载。
- IMU 高频传播。
- LiDAR-to-map EKF 更新。
- 相机质量门控。
- 高频/低频 odom 和 path 发布。

代码中已经加入详细中文注释，方便后续改成 C++ 或写论文方法部分。

### `scripts/pcd_to_npz_map.py`

地图转换工具。把 FAST-LIVO2 输出的 PCD 地图转换为 NPZ，降低机器狗端启动加载时间和内存压力。

### `scripts/make_initial_pose_yaml.py`

生成初始位姿 YAML 的辅助工具。机器狗实测时，如果知道初始点，可以用它快速写配置。

### `config/dog_prior_map_localization.yaml`

主要参数文件，包括：

- ROS frame 和 topic。
- 先验地图路径。
- LiDAR/Camera/IMU 外参。
- IMU 噪声。
- 地图匹配参数。
- 相机质量门控参数。
- 输出话题配置。

### `launch/dog_prior_map_localization.launch`

启动文件。加载配置并启动主节点。

### `docs/机器狗端低算力先验地图定位算法报告.md`

本文档，说明算法原理、文件作用和后续改进方向。

已完成：

   - `/dog_livo/path_high_rate`
   - `/dog_livo/path_corrected`

## 9. 后续需要继续做的事情

当前版本是原型，能体现老师要求的结构，但要真正上机器狗，还建议继续做：

1. 把 Python KDTree + EKF 更新迁移到 C++，进一步降低 CPU 占用。
2. 把点到点残差改成点到面残差，提高地图匹配精度。
3. 加入局部地图裁剪，而不是全图 KDTree 查询。
4. 加入视觉特征重投影约束。
5. 加入退化检测：长走廊中 LiDAR 退化时，提高地图/视觉约束权重。
6. 加入初始重定位模块，例如 NDT/ICP 粗定位或人工给初值。
7. 实机测试 CPU、频率、延迟和定位误差。
